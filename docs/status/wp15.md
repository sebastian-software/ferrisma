## Decisions applied

The brief fixed these shapes; where this page departs from it, the reason is
given here and under the deviations.

- **Chunk lists are vectors, data is `Cow`.** `WebPMux<'a>` holds one
  `Vec<WebPChunk<'a>>` per C list (`iccp`, `exif`, `xmp`, `anim`, `vp8x`,
  `unknown`) and `images: Vec<WebPMuxImage<'a>>`, with the insertion and search
  order of `ChunkSetHead`, `ChunkAppend`, `ChunkSearchList`, `MuxImagePush` and
  `MuxImageGetNth`. `WebPMuxImage<'a>` keeps `header`, `alpha` and `img` as
  `Option<WebPChunk<'a>>` and `unknown` as a vector. `WebPChunk<'a>` is `{ tag,
  data: WebPData<'a> }`: the `Cow` is borrowed where C's chunk does not own its
  bytes and owned where it does, so C's `owner` flag has no field; C's `next`
  is the position in the vector.
- **Lifetimes of lent bytes.** Every function that takes data from the caller
  takes `&WebPData<'a>`, the bytes' lifetime, not `&'a WebPData<'_>` as the brief
  proposed for `webp_mux_create`. With `copy_data == 0` the mux keeps borrowed
  bytes for `'a`; with `copy_data == 1` the data may be a short borrow, which the
  animation encoder needs to push its own frames into its mux. `GetImageData`
  calls `WebPMuxCreate(bitstream, 0)` on the caller's bitstream and keeps the
  image and alpha bytes of that temporary mux for the caller's mux; with a
  borrow of the `WebPData` struct (the brief's form) those bytes could not
  outlive the temporary. The lent and the merely readable bytes are told apart
  by `ChunkBytes` (`src/mux/muxi.rs`, deviation 2). A `WebPData` that owns its
  bytes cannot be lent and is copied even without copying.
- **Results.** `WebPMuxError` (an `i32` newtype, C's values) and `WebPChunkId`
  (a `u32` newtype) are in `src/webp/mux.rs`. Functions that C writes through
  output pointers return `Result<T, WebPMuxError>`; `WebPMuxGetChunk` returns
  `Result<&WebPData<'a>, _>` into the mux, `WebPMuxGetFrame` a
  `WebPMuxFrameInfo<'static>` with an owned bitstream, `WebPMuxAssemble` the
  assembled `WebPData<'static>`. `WebPMuxDelete` and `WebPAnimEncoderDelete` are
  the drops, kept as functions.
- **Animation encoder.** `WebPAnimEncoder<'a>` owns its `WebPMux<'a>`, not the
  brief's `WebPMux<'static>`, so that `WebPAnimEncoderSetChunk` with
  `copy_data == 0` lends chunk bytes for `'a` (accepted by the integrator on 9
  November 2026); the frames are always copied (`WebPMuxPushFrame(..., 1)` in
  `FlushFrames`). It also owns the three canvases as `WebPPicture<'static>`, the frame ring
  (`Vec<EncodedFrame>` with `start`, `count`, `flush_count` as C's indices), both
  configurations, the options and the error string. C's `curr_canvas` is the
  frame argument of the functions that read it.
- **Views of the canvas (the brief's open question).** C makes
  `WebPPictureView`s of the current canvas in `GetSubRect` and encodes them later
  in `EncodeCandidate`. Between the two, `IncreaseTransparency`,
  `FlattenSimilarBlocks` and `CopyCurrentCanvas` change the canvas, which the view
  sees, and the lossless encoding writes into the canvas through the view
  (`WebPReplaceTransparentPixels` unless `exact`), which the lossy candidate of
  the same frame then encodes. WP9's shared view would copy its planes before
  that write (WP13 deviation 1) and lose it. The translation therefore checks
  the rectangle where C makes the view and makes the view where it is used: a
  shared `webp_picture_view` for `WebPGetColorPalette`, and for an encoding a
  picture that borrows the canvas's ARGB samples exclusively as
  `PlaneStorage::External` (`sub_frame_view`), as the C ABI lends caller memory.
  No WP9 interface changes. Evidence: with a shared view, the "patchy" cases of
  `option_and_config_matrix_matches_the_c_encoder` (noisy opaque content, so
  that the lossy candidate wins, next to transparent pixels that keep a color)
  give other bytes than C.
- **C ABI** (ADR 0004): `src/abi/mux.rs`, modelled on `src/abi/demux.rs`, with the
  public `WebPData` mirror of `src/abi/demux.rs`. Because the mux borrows the
  bytes and not the `WebPData` struct, the caller's bytes (of `WebPMuxCreate`,
  the setters and `WebPAnimEncoderSetChunk`) are lent as a `'static` borrow
  under the header's contract, with no leaked box per input (deviation 17); the
  handle is a box of the mux, or of the encoder with its error buffer.
- **Consumer builds** (`tools/oracle/probes/wp15/oracle.cmake`): `webpmux`,
  `img2webp` and `anim_diff`, each against both libraries, with
  `upstream/libwebp/src` first in the include path.

### Interface change in the WP13 module

One commit, `refactor(abi): share the picture conversion of encode.h with the mux
ABI`, makes `Mode`, `with_picture` and `progress_closure` of `src/abi/encode.rs`
`pub(crate)`. `WebPAnimEncoderAdd` converts the caller's frame for one call
exactly as `WebPEncode` does: the ARGB plane (or, without `use_argb`, the YUVA
planes that `WebPPictureYUVAToARGB` reads) is lent, the results are written back
(the error code and, after a conversion, the new ARGB block), and the frame's C
progress hook is wrapped as a closure. PORT_STATUS.md's note for WP15 named
`picture_to_rust` and `picture_to_c`; `with_picture` is the function around them
that every encode ABI entry point uses, so `src/abi/mux.rs` needs nothing else.
No behavior changes. The integrator decided this form on 9 November 2026 (an
interface change to a merged module, in its own commit): `Mode`, `with_picture`
and `progress_closure` become crate-visible, and `picture_to_rust`,
`picture_to_c`, `Converted`, `Refused` and `set_error` stay private.

builds and runs the tests with the `oracle` feature. Byte strings are compared

### Mutation checks

Twenty-one mutations were tried, one at a time, each against the WP15 tests (the
ABI ones with the Rust-linked probes relinked). Twenty are caught;
`ChunkSearchList`'s check of a missing nth chunk is equivalent for every caller

penalty, the undecided-candidate rule of the dispose-background trial, the

## Not-applicable checks

1. **`NULL` arguments and `NULL` bytes** exist only at the C ABI (PORTING rule 8);
   every `NULL` case of `mux.h` is compared there. The Rust API takes references,
   and an empty `WebPData` it is given is an empty, non-null slice (C rejects only
   `NULL` bytes).
2. **Pointer values** are never printed: the probes print whether a pointer is
   `NULL` or unchanged, and digests of the bytes.
3. **Big-endian targets** are not run. `DecodeFrameOntoCanvas` reads the decoded
   BGRA bytes as native-order words, as C's `uint32_t*` view does.
4. **32-bit targets** are not run; `ENCODED_FRAME_SIZE` follows the pointer width
   and the encoder never allocates more than 31 frames.
5. **Allocation failures** (`WEBP_MUX_MEMORY_ERROR`, `VP8_ENC_ERROR_OUT_OF_MEMORY`)
   are not injected; the translation reserves fallibly where C allocates
   (`try_reserve` for list elements, `webp_safe_malloc` for chunk and output
   bytes) and returns C's codes.
6. **`WebPAnimEncoderRefineRect`** is declared in an internal header, so the C
   ABI does not export it; the probe and the test call it on each side directly.
7. **GIF input** to `anim_diff` and `img2webp` needs giflib, which neither build
   uses; `img2webp`'s PNG, JPEG and TIFF readers depend on the host's libraries,
   which both builds share, and the tests read PAM. `img2webp -version` calls
   `SharpYuvGetVersion`, which the Rust library does not export (WP13's stand-in
   aborts), and is not run.
8. **Threads**: `thread_level` 0 and 1 are matrix dimensions; the encoder adds no
   thread of its own.

## Undefined behavior excluded from the oracle (PORTING rule 8)

1. **`WebPMuxSetCanvasSize` with an area from 2^31 to 2^32:** after the area test
   in `uint64_t`, C computes `width * height` in `int`, which overflows. The
   translation panics in the dev and `checked` profiles and wraps in release,
   where the result is C's on wrapping hardware. The generated canvas sizes avoid
   this range; `WebPAnimEncoderAssemble` reaches it only for canvases of 2^31
   pixels and more.
2. **Fourcc characters from 0x80 on:** `MKFOURCC` promotes `char`, which is signed
   on macOS ARM64 and x86-64, so the first character sign-extends and the second
   and third shift a negative `int`. The translation takes unsigned bytes (C's
   result where `char` is unsigned). The tests use ASCII fourccs.
3. **`WebPAnimEncoderAdd` after `WebPAnimEncoderAssemble`:** the flushed encoder
   has no frame left, and `IncreasePreviousDuration` reads `GetFrame(enc,
   count - 1)`, which fails C's assertion and indexes before the ring in release.
   The translation wraps the `size_t` arithmetic as C does and panics where the
   index leaves the vector. Not generated.
4. **`FrameToFullCanvas` when its second encoding fails:** C frees the first
   encoding's bytes and `OptimizeSingleFrame` frees them again (a double free).
   In C the stale progress hook can make the second encoding fail; the
   translation calls no hook there (deviation 10), and only a memory error
   remains, which is not injected.
5. **`WebPAnimEncoderRefineRect` with a rectangle that clips to nothing** fails
   the assertion of `MinimizeChangeRectangle`'s pixel comparison, and with a
   quality outside [0, 100] converts a NaN to `int`. The test skips both.

C assertions excluded from the oracle (the `debug` oracle aborts, and the
translation's `debug_assert!` fails in the dev and `checked` profiles):

1. **`GetAdjustedCanvasSize`'s `assert(x_offset < MAX_POSITION_OFFSET)`** (and
   the one for `y_offset`): a parsed `ANMF` chunk holds offsets up to `2 * (2^24
   - 1)`, so `WebPMuxAssemble` of a parsed animation with such a frame fails the
   assertion; in release, C and the translation go on and refuse the canvas size.
   The truncation test skips bit flips that give such a frame
   (`asserts_in_assembly`, 1 of the 264 bit flips).
2. **`MinimizeChangeRectangle` with an empty rectangle** (exclusion 5 above).

## Recorded deviations

1. **Lists and ownership** (decision above). C's `NULL` bytes inside a mux (an
   empty copy, `WebPDataCopy` of empty data) are an owned empty `WebPData`
   (`data_is_null`); `CreateVP8XChunk` tests them for the metadata flags and the
   image, as C tests `bytes != NULL`, and the C ABI hands them out as `NULL`.
   Functions that return C's next list element return nothing; `ChunkAppend` needs
   no cached list end (`chunk_list_ends`); `ChunkSetHead` takes the chunk and leaves
   it initialized, where C clears its `owner` flag, so `MuxImageParse` reads a
   chunk's size before handing it over.
2. **Lent and readable bytes** (decision above). `ChunkAssignData` takes a
   `ChunkBytes`: lent bytes (a borrowed `WebPData`, or the parsed bytes of a
   borrowed input) are kept without copying as in C; readable bytes (an owned
   `WebPData`, a local buffer) are copied even with `copy_data == 0`, and empty
   readable bytes become an empty borrowed slice, a non-null pointer to no bytes
   as C keeps it. `GetImageData` creates its temporary mux over the bitstream's
   bytes and keeps the image and alpha slices of it, lent or readable as the
   bitstream was.
3. **Results.** `WebPMuxGetFrame` returns the frame; on a memory error C has
   already written the other fields, which only the C ABI reproduces. The reset of
   the caller's `WebPData` that `MuxGet` performs before a known chunk is not
   found is done by the C ABI (`WebPMuxGetChunk`). `WebPAnimEncoderAssemble` keeps
   C's output parameter (`&mut WebPData<'static>`), because C writes it also when
   the single-frame optimization fails.
4. **Unreachable `NULL` checks.** `MuxValidate`'s `NULL` mux and
   `ChunkAssignData`'s `NULL` data have no counterpart; `MuxImageCount` and
   `GetImageInfo` panic where C dereferences `NULL` for ids or images that no
   caller passes.
5. **Objects as values.** `WebPNewInternal`, `WebPMuxCreateInternal` and
   `WebPAnimEncoderNewInternal` allocate no object block (a value cannot fail);
   their other allocations fail as C's. The frame ring is reserved with
   `webp_safe_calloc(size, ENCODED_FRAME_SIZE)`, C's `sizeof(EncodedFrame)`.
6. **Sub-frame views** (decision above): `GetSubRect` checks the rectangle with
   `webp_picture_view` and drops the view; `GenerateCandidates` makes a shared
   view for the palette count and an exclusive one for each encoding.
7. **`EncodeFrame`** removes the memory writer from the picture after the call,
   where C leaves `writer` and `custom_ptr` set (C never encodes the picture again
   without setting them); the writer holds the memory writer through an
   `Rc<RefCell<...>>`, because the canvas copy is a `WebPPicture<'static>`.
8. **`DecodeFrameOntoCanvas`** decodes into a zeroed buffer with the view's
   stride and size (`MODE_BGRA`) and copies its rows into the canvas as
   native-order words, also after a failed decoding, so the canvas holds what C's
   decoding into the view leaves.
9. **`SubFrameParamsFree`** has no counterpart: the views are dropped where they
    are used.
10. **Progress hook.** C copies the frame's `progress_hook` and `user_data` into
    the canvas copy (`CopyCurrentCanvas`) and from there into each view. The views
    here call the frame's hook through a borrow, so every candidate encoding
    reports as in C. The canvas copy holds no hook, so the re-encoding of the
    canvas in `WebPAnimEncoderAssemble` (`FrameToFullCanvas`, for a single frame
    smaller than the canvas) reports nothing, where C calls the last frame's hook
    with that frame's `user_data`, which the header does not promise to keep
    valid. The tests accept C's count there (2 cases) and require 0.
11. **`OptimizeSingleFrame`** drops its temporary mux before it replaces
    `webp_data`, which the mux borrows; C replaces it first and deletes the mux
    after. The same bytes result.
12. **Error string.** A `String` cut to `ERROR_STR_MAX_LENGTH - 1` bytes, as
    `snprintf` cuts it; the C ABI keeps a NUL-terminated copy in the encoder's box,
    updated at the end of every call that changes it, so a pointer that
    `WebPAnimEncoderGetError` returned earlier shows later errors, as C's does.
13. **Verbose output** (`SanitizeEncoderOptions`, `FlushFrames`, the YUV warning)
    goes to `std::io::stderr`, unbuffered like C's `stderr`; write errors are
    ignored, as `fprintf` ignores them.
14. **Fourcc arguments** are `&[u8; 4]` (exclusion 2).
15. **`WebPMuxPushFrame`** copies only the scalar fields of the frame for its
    checks (C copies the struct, which shares the bitstream pointer).
16. **C ABI frames.** `WebPAnimEncoderAdd` converts the frame with WP13's
    `with_picture`; a frame that it cannot lend (WP13's rejected layouts: a
    negative stride over several rows, overlapping planes, a misaligned ARGB
    plane) records `VP8_ENC_ERROR_INVALID_CONFIGURATION` and the error string
    "ERROR adding frame: the C ABI cannot lend the frame's planes.", where C would
    encode it. The frame's C hook is called with the frame's pointer
    (`progress_closure(hook, frame)`), where C copies `progress_hook` and
    `user_data` from the frame into the canvas copy (`anim_encode.c` lines 834
    and 835) and calls the hook with its sub-frame view's pointer: `user_data`
    matches, the pointer identity does not. A hook must not touch the frame
    (WP13 deviation 15).
17. **C ABI lending.** The caller's bytes are lent to the mux as `'static`
    borrows with no box per input, because the mux keeps the bytes, not the
    `WebPData` struct. They must not change while the mux may read them, which the
    header implies; C would read the changed bytes.
18. **C ABI partial structs.** `WebPMuxGetFrame` writes the fields one by one and
    never `pad`, as C; `WebPAnimEncoderOptionsInitInternal` writes only the fields
    that C writes, and `WebPAnimEncoderNewInternal` reads only the fields that the
    encoder uses (C copies the struct), so uninitialized padding is never read.
    `WebPAnimEncoderAssemble` writes the caller's `WebPData` only where C writes it
    (a marker detects whether the translation reached `WebPMuxAssemble`).
19. **Fuzz targets.** The FuzzTest domains are `arbitrary` tuples (modulo for the
    ranges); `animencoder_fuzzer` drops the unused input string and the SIMD
    optimization index, returns on an empty frame list and ignores frames past 15;
    the targets keep upstream's names (cargo's `non_kebab_case_bins` warning, as
    WP12 records).

## Notes for the packages that build on WP15

### WP16 (safe decoder API)

- **Reading metadata.** Two paths read the `ICCP`, `EXIF` and `XMP ` chunks of a
  file:
  - the demuxer (WP8): `webp_demux(&data)` (or `webp_demux_partial` for
    incomplete data), then `webp_demux_get_chunk(&dmux, *b"ICCP", 1)` and
    `webp_demux_next_chunk` for further chunks of the same tag; it borrows the
    input, copies nothing, accepts partial files and returns every chunk of a tag
    (files may carry several `EXIF` chunks). For an animation,
    `webp_anim_decoder_get_demuxer(&dec)` gives the decoder's demuxer.
  - the mux: `webp_mux_create(&data, 0)` then `webp_mux_get_chunk(&mux, b"ICCP")`
    (`Result<&WebPData, WebPMuxError>`); it parses and validates the whole file
    (`MuxValidate` rejects, among others, a second `ICCP` chunk, VP8X flags that
    disagree with the chunks, and incomplete files) and returns only the first
    chunk of a tag.
- **Recommendation:** the safe decoder API reads metadata through the demuxer.
  It is the decoder side's container parser (imageio's `ReadWebP` and `cwebp
  -metadata` use it), it shares the borrowed input with the decoding, and it does
  not reject files that the decoder accepts. The mux is for editing and writing
  containers.

### WP22 (Ferrixel `webp-write`)

- **Metadata around an encoded image.** Wrap `webp::api::encode`'s output (a
  complete WebP file) with the mux:

  ```rust
  let image = WebPData { bytes: Cow::Borrowed(&encoded) };
  let mut mux = webp_mux_new().expect("current ABI");
  webp_mux_set_image(&mut mux, &image, 0)?; // VP8/VP8L, with ALPH if any
  webp_mux_set_chunk(&mut mux, b"ICCP", &WebPData { bytes: Cow::Borrowed(&icc) }, 0)?;
  webp_mux_set_chunk(&mut mux, b"EXIF", &WebPData { bytes: Cow::Borrowed(&exif) }, 0)?;
  webp_mux_set_chunk(&mut mux, b"XMP ", &WebPData { bytes: Cow::Borrowed(&xmp) }, 0)?;
  let file: WebPData<'static> = webp_mux_assemble(&mut mux)?; // owned bytes
  ```

  `webp_mux_assemble` writes the VP8X chunk with the ICC, EXIF, XMP and alpha
  flags and the chunk order of the WebP specification (`VP8X`, `ICCP`, `ANIM`,
  the image, `EXIF`, `XMP `, unknown chunks), as `cwebp -metadata` does. Borrowed
  data (`copy_data == 0`) must outlive the mux. Two C behaviors to know: an empty
  payload set with `copy_data == 1` becomes C's `NULL` bytes, so the VP8X flag is
  not set and `webp_mux_assemble` fails with `WEBP_MUX_INVALID_ARGUMENT` (skip
  empty metadata); and a second unknown chunk of another tag is refused with
  `WEBP_MUX_NOT_FOUND`. Canvas sizes passed to `webp_mux_set_canvas_size` with an
  area from 2^31 to 2^32 panic in debug builds (exclusion 1); a safe API checks
  them first.
- **Animations.** `webp_anim_encoder_new(width, height, Some(&options))`
  (`webp_anim_encoder_options_init` first; `kmin`, `kmax`, `minimize_size`,
  `allow_mixed`, loop count and background color); then for each frame a
  `WebPPicture` of the canvas size (ARGB, or YUVA, which is converted) and
  `webp_anim_encoder_add(&mut enc, Some(&mut picture), timestamp_ms,
  Some(&config))`, where the frame lasts until the next timestamp and frames equal
  to the previous one are merged; then `webp_anim_encoder_add(&mut enc, None,
  end_ms, None)` for the last duration, metadata with
  `webp_anim_encoder_set_chunk`, and `webp_anim_encoder_assemble(&mut enc, &mut
  data)`. Errors are `false` with `webp_anim_encoder_get_error(&enc)` and the
  frame's `error_code`. A frame's progress hook reports every candidate encoding.
  The output is byte-identical to C's for the same frames and settings.

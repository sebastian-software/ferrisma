## Checkpoint (2026-11-08)

ADR 0006 states the public types and functions, their ownership and
lifetimes, the error type, the validation rules, the mapping of every item to
the translation, and the module layout. A throwaway prototype (not committed)
confirmed the one non-obvious part: a `Picture<'a>` that lends its planes to a
`WebPPicture` per call, so that the writer, hook and statistics need not
outlive the planes, encodes byte-identically to `webp_encode`, re-encodes, and
is `Send` and `Sync`. Decisions for the integrator:

1. **ADR 0006.** Accept, or change names and shapes.
   Recommendation: accept.
2. **Module skeleton.** The API needs `pub mod api;` in `src/lib.rs`, a
   `src/api/mod.rs`, `"api"` in `TOP_LEVEL` of `tools/units.py` and an `api`
   list in `tools/units.json` (WP0's files). Options: (a) WP17 adds them in a
   separate commit, with a header-only `src/api/decode.rs` owned by WP16;
   (b) the integrator lands them on `main` first; (c) WP17 adds only `encode`,
   and WP16 later adds its line to `src/api/mod.rs`. Recommendation: (a), so
   that WP16 only fills its file.
3. **`LOSSLESS_DEFAULT_QUALITY`** (the 70 of the lossless simple API) is a
   private constant of WP13's exception in `src/enc/picture_enc.rs`. Options:
   (a) make it `pub(crate)`, one line in its own commit; (b) the API keeps its
   own 70, which the differential test against C's `WebPEncodeLossless*` pins
   (WP13's mutation check shows that a repetitive picture catches 69, 71 and
   75). Recommendation: (a).
4. **Gate (e) wording.** The brief and `docs/PORT_PLAN.md` (Phase 6) say that
   lossy output is "full-range BT.601". The pinned code is limited range:
   `src/dsp/yuv.h` documents Y in [16, 235] and U and V in [16, 240], and
   `VP8RGBToY` adds `16 << YUV_FIX` (lines 12 to 28 and 211 to 213); SharpYUV's
   WebP matrix has the same offsets. ADR 0006 states limited range.
   Recommendation: correct PORT_PLAN.md and tell WP16, whose decoder converts
   back with the same matrix (`VP8YUVToR`).
5. **Simple API.** `encode_lossy` and `encode_lossless` run the steps of C's
   `Encode` through `Picture::import` and `Encoder`, instead of calling the
   translation's `webp_encode_*`, which return `None` without the recorded
   code. The bytes are the same (tested against C's eight functions); the
   caller gets the error code, and RGBX and BGRX work too.
   Recommendation: accept.
6. **Misuse cases.** Negative dimensions and strides cannot be expressed
   (`u32`, `usize`), so the property test covers zero, too large and too
   short values. "Odd strides for YUV" is read as a chroma stride below
   `(width + 1) / 2` for an odd width. Recommendation: confirm the reading.
7. **Evidence without a WP17 probe.** WP17 has no C unit; the differential test
   replays WP13's case records through the API and compares with WP13's
   probes in a separate process (all printed keys except `pic=`, because the
   API does not expose planes; `caller=` still shows what the encoder wrote
   into caller memory). Views and `extra_info` are not in the API, so those
   cases are left out. Recommendation: accept; no `tools/oracle/probes/wp17/`.

Until the decision, nothing outside this page and the ADR changes.

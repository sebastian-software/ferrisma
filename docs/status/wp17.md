# WP17: safe encoder API

- Status: complete. [ADR 0006](../adr/0006-safe-encoder-api.md) is accepted
  (integrator, 2026-11-08) and implemented as `webp::api::encode` in
  `src/api/encode.rs`. Every encoding calls the translated `WebPEncode`
  (`webp_encode`) with the stored `WebPConfig`; the API replays of WP13's

## Decisions applied

The checkpoint of 2026-11-08 proposed ADR 0006 with seven decisions; the
integrator accepted all of them as recommended:

1. ADR 0006 as proposed; its status is `accepted` in the implementation's
   pull request.
2. WP17 adds the `src/api` skeleton in its own commit (below).
3. `LOSSLESS_DEFAULT_QUALITY` becomes `pub(crate)` in its own commit (below).
4. Lossy output is BT.601 in limited range, not full range; WP17 corrected
   `docs/PORT_PLAN.md` (below), and WP16 is told (notes).
5. `encode_lossy` and `encode_lossless` run C's `Encode` steps through
   `Picture::import` and `Encoder`.
6. Misuse: negative sizes and strides are unrepresentable; "odd strides for
   YUV" is a chroma stride below `(width + 1) / 2` at an odd width.
7. Evidence replays WP13's records and probes, on every printed key except
   `pic=`; no `tools/oracle/probes/wp17/`.

The integrator added two requirements, both applied: the rustdoc of
`PixelRows`, `YuvaPlanes` and `Picture::from_argb` states that strides count
elements of the slice's type (bytes, or `u32` pixels), and `Encoder::encode`
and `encode_to` document that a panicking callback leaves the picture without
planes, after which an encoding returns `NullParameter` (tested).

## Not-applicable checks

1. **Source correspondence.** WP17 translates no upstream unit, so there are no
   `// upstream:` markers, no `tools/rust_name.py` names and no probe of its
   own (decision 7).
2. **`NULL` arguments** do not exist in the API (references and slices).
3. **Views, crop, rescale, distortion, alpha blending, `extra_info` and the
   standalone conversions** are not in the API (ADR 0006); their WP13 cases
   are left out or run without the map. Metadata chunks and animation are
   WP15's.
4. **`pic=`.** The API does not expose a picture's planes; the caller's buffers
   (`caller=`), the output and the statistics show the encoder's effects.
5. **Undefined behavior in C.** WP13's exclusions hold through its case records
   (statistics of alpha with `alpha_compression` 0 and of failed threaded alpha
   encodings, `extra_info_type` 6), and the simple-API test skips
   `WebPEncodeLosslessRGBA` on misaligned rows. The API accepts such rows; the
   translation reads them as bytes, which C cannot confirm.
6. **Allocation failures** are not injected; `OutOfMemory`, `BadWrite` from a
   refused memory-writer growth and `Unreported` are reached only through the
   translation's fallible reservations.
7. **Floating point** results (PSNR) are compared bit for bit on this host;
   equality on other hosts is recorded, not assumed.
8. **32-bit targets** are not run; the `usize` overflow of a plane's extent maps
   to `InvalidStride` and is reachable there only.
9. **`cargo doc --no-deps`** reports no warning from `src/api`; the 15 warnings
   it prints come from `src/abi`, `src/dec`, `src/enc`, `src/dsp` and
   `src/sharpyuv` (intra-doc links to private items and similar), outside this
   package.

## Recorded deviations

Differences between the API and C's encoder API, each stated in ADR 0006:

1. **Early refusal of dimensions.** Widths and heights above 16383 are refused
   with `InvalidDimensions` before anything is allocated; C imports them and
   fails in `WebPEncode` with `VP8_ENC_ERROR_BAD_DIMENSION`. Zero dimensions are
   refused as well, where C fails the import.
2. **Floats.** A NaN or infinite `quality` or `target_psnr` is refused with
   `InvalidParameter`; C accepts it and converts it to an integer, which is
   undefined. A quality outside 0 to 100 is `InvalidParameter`, where C reports
   `INVALID_CONFIGURATION` (or `WebPConfigPreset` returns 0).
3. **Row strides of the X layouts** must hold four bytes per pixel, and the last
   row `width * bytes_per_pixel` bytes; C checks three bytes per pixel, which
   lets RGBX and BGRX rows overlap, and reads `4 * width - 1` bytes of the last
   row.
4. **Negative strides and dimensions** cannot be expressed (`u32`, `usize`), so
   bottom-up rows are not accepted (C reads them upward; WP9 deviation 7 panics
   on them in the translation).
5. **`Encoder::encode`** returns the bytes only on success; C's memory writer
   keeps the partial output of a failed encoding. Its vector keeps the memory
   writer's capacity, up to twice the length.
6. **`target_size`** takes a `u32` and saturates at `i32::MAX`, C's `int`.
7. **Panicking callbacks** leave the picture without planes; C has no panics.
8. **The simple functions** return the recorded error instead of C's 0, and
   accept RGBX and BGRX, which C's simple API lacks; their bytes are C's.
9. **A successful encoding is `Ok`** even when libwebp recorded
   `VP8_ENC_ERROR_USER_ABORT` at a report whose answer it ignores
   (`ResetAllMBInfo` in `src/enc/analysis_enc.c`, and `StatLoop`, whose result
   `VP8EncLoop` in `src/enc/frame_enc.c` drops for lossy methods 0 to 2); C
   returns 1 and leaves the code in the picture, which the API does not expose
   on success.
10. **Callbacks** receive no picture (ADR 0003, as in the translation).

## Upstream behavior preserved

- The encoder writes into the picture's planes unless `exact`: the Y, U and V
  samples under fully transparent 8 by 8 blocks (lossy), every transparent ARGB
  pixel to 0 (lossless), and with `show_compressed` the decoded samples. A
  second encoding of a picture sees these writes and the planes of the first
  encoding's conversion.
- A lossy encoding of ARGB samples converts with sharp YUV or dithering when
  configured; an import into YUVA converts at once without them.
- `WebPConfigLosslessPreset` overrides `lossless`, `method` and `quality`.
- libwebp ignores the progress hook's answer at the end of an analysis without
  segments and during the statistics pass of lossy methods 0 to 2; the
  documentation of `Encoder::progress` tells a cancelling hook to keep
  returning `false`.

## ADR-0018 gate (e): the encoder's semantics

- **Lossy color.** Y'CbCr after ITU-R BT.601 in limited range (Y 16 to 235, Cb
  and Cr 16 to 240), from 8-bit RGB with the fixed-point constants of
  `src/dsp/yuv.h` (`VP8RGBToY`, `VP8RGBToU`, `VP8RGBToV`, 16-bit fixed point),
  4:2:0 with each chroma sample averaged from its 2 by 2 block (centered) in
  gamma-corrected light, weighted by alpha where the block is translucent; or,
  with sharp YUV, SharpYUV's iterative conversion with the same WebP matrix.
  The decoder converts back with the same limited-range matrix (`VP8YUVToR`
  and friends). Planes from `Picture::from_yuva` are encoded as given, so a
  caller that converts itself must produce limited-range BT.601.
- **Lossless.** ARGB samples are stored exactly, except that transparent
  pixels become 0 unless `exact`, and `near_lossless` below 100 changes values.
- **Alpha.** Input alpha is straight; the encoder has no premultiplied input.
  Lossy alpha is a separate plane, lossless at `alpha_quality` 100 and
  quantized below; samples under transparency change unless `exact`.
- **Color signal.** The output carries no `ICCP` chunk and no color metadata;
  RGB values are written as given, and readers assume sRGB unless a profile is
  muxed in (WP15).
- **Orientation.** None; an `EXIF` chunk is WP15's.
- **Depth.** 8 bits per channel.

## Notes for the packages that build on WP17

- **WP22 (Ferrixel `webp-write`).**
  - *Quality and speed.* Ferrixel's `quality: f32` (1 to 100) maps directly to
    `Config::preset(Preset::Default, quality)` (or another preset, which also
    changes SNS and filters). Its `speed: u8` (1 slowest to 10 fastest) maps to
    `method((6 * (10 - speed) + 4) / 9)`, which gives 6, 5, 5, 4, 3, 3, 2, 1,
    1, 0. For lossless output, `Config::new().lossless_level(10 - speed)` sets
    method and quality together (level 9 smallest, 0 fastest); `quality` then
    has no further meaning, and `near_lossless` offers a lossy-lossless middle.
    `multithreaded` changes the output bytes but does not depend on the
    machine, so fix it per option set, as the AVIF sink fixes its tiles.
  - *Budgeted frame.* Reserve `width * height * 4` bytes from the budget as a
    `Vec<u32>`, write each straight RGBA8 row as it arrives with
    `u32::from_be_bytes([a, r, g, b])` (pinned by
    `rgba_rows_packed_as_argb_words_encode_as_the_importer`), then call
    `Picture::from_argb(&mut frame, width, height, width as usize)` and encode.
    The output equals `cwebp`'s for the same RGBA. A lossless encoding needs no
    further sample memory; a lossy one converts into YUV planes that the
    picture keeps: `picture.owned_sample_bytes()` after the encoding reports
    them (`w * h + 2 * ceil(w / 2) * ceil(h / 2)`, plus `w * h` when a pixel is
    not opaque). The encoder's internal state is not observable; report it as
    unbounded, as the AVIF sink does. A lower-memory lossy route is
    `Picture::from_yuva` with the sink's own conversion into budgeted planes
    (limited-range BT.601); its colorimetry is then the sink's, not
    `cwebp`'s.
  - *Writes into the frame.* Unless `exact(true)`, the encoder rewrites
    transparent areas of the frame; set it when the frame is reused.
  - *Output.* `Encoder::encode` returns the complete RIFF WebP file (`VP8 `,
    `VP8L`, or `VP8X` with `ALPH` for lossy with alpha); its capacity can be up
    to twice its length, so `shrink_to_fit` a retained result, or stream with
    `encode_to`. `Picture` is `Send` and `Sync`; the writer and the hook run on
    the calling thread.
  - *Cancellation and errors.* A progress hook that returns `false` aborts with
    `UserAbort`; keep returning `false` (deviation 9). `InvalidParameter`,
    `InvalidConfiguration`, `InvalidDimensions`, `InvalidStride` and
    `BufferTooShort` are option or input errors; the rest are encoder failures.
- **WP16 (safe decoder API).** The decoder converts lossy output back with the
  same limited-range BT.601 matrix (`VP8YUVToR`, `VP8YUVToG`, `VP8YUVToB`,
  `src/dsp/yuv.h` lines 12 to 28); its gate (e) statement should say limited
  range. `src/api/decode.rs` exists with its header, and `src/api/mod.rs`
  already declares it.
- **WP15 (mux).** Metadata (`ICCP`, `EXIF`, `XMP`) and animation wrap the API's
  output or the translation's; the API exposes neither.

# WP14: animation decode and demux ABI

- Status: every unit of the WP14 inventory is translated: `src/demux/anim_decode.c`,
  the two exceptions in `src/webp/demux.h`, and the C ABI of every function of
  `src/webp/demux.h`. The animation decoder agrees with the C oracle on every
  compared input, through the Rust API and through the C ABI; upstream's
  `anim_dump`, unmodified and linked against the Rust library, writes the same
  files as against the C library. The demux link stand-ins of the consumer
  build are gone.

- Model: Claude Opus 5.5 (`claude-opus-5-5`)
- Depends on: WP8 (the demuxer and its iterators; takes over its module for
  integration fixes), WP12 (`webp_get_features`, `webp_init_decoder_config`,
  `webp_decode`, `PlaneStorage::External`), WP1 (`WebPData`, the `WEBP_MUX_*`

- Probes: `tools/oracle/probes/wp14/`; tests: `tests/wp14_*.rs` with

## Decisions applied

The brief fixed these shapes; each is recorded under the deviations where it
changes a representation.

- **Ownership.** `WebPAnimDecoder<'a>` owns the `WebPDemuxer<'a>` that it creates
  from the caller's `&'a WebPData`, both canvases (`curr_frame`,
  `prev_frame_disposed`, reserved fallibly by `webp_safe_calloc`), the info, the
  blend row function, the previous timestamp, the keyframe flag and the next
  frame index. `webp_anim_decoder_new(data, options) -> Option<WebPAnimDecoder>`.
- **Previous iterator.** C keeps a `WebPIterator` whose `private_` points at the
  decoder's own demuxer. The decoder keeps the plain fields that `IsKeyFrame`,
  `FindBlendRangeAtRow` and the dispose step read (`IteratorFields`) and builds
  the current frame's iterator in each `GetNext` call with
  `webp_demux_get_frame(&self.demux, n)`.
- **Decoder configuration per call.** The decoder keeps the decoder options and
  the colorspace (C: `config.options`, `config.output.colorspace`) and attaches
  the canvas to a `WebPDecoderConfig` built for each frame as
  `PlaneStorage::External` (ADR 0003, "Decoding context per call").
- **API shapes.** `webp_anim_decoder_get_next(&mut dec) -> Option<(&[u8], i32)>`
  (canvas and timestamp), `webp_anim_decoder_get_info(&dec) -> WebPAnimInfo`,
  `has_more_frames`, `reset`, `get_demuxer(&dec) -> &WebPDemuxer`, and
  `webp_anim_decoder_delete(dec)` as the drop. Only `MODE_RGBA`, `MODE_BGRA`,
  `MODE_rgbA` and `MODE_bgrA` are accepted. C's widths are kept in the canvas
  arithmetic (`(size_t)size != size`, the `uint64_t` products, the `uint32_t`
  pixel indexes).
- **C ABI handles.** The demuxer borrows the `WebPData` value, so the ABI leaks a
  `Box<WebPData<'static>>` over the caller's bytes (which `demux.h` requires to
  stay valid and unchanged), creates the demuxer from it and returns a heap
  handle whose first field is the demuxer; `WebPDemuxDelete()` drops the
  demuxer, then frees the box. The animation decoder is held the same way.
- **`src/webp/mux.h`** is a reviewed include of `anim_decode.c`
  (`tools/units.json`): only the `WEBP_MUX_*` enums of `mux_types.h` are used,
  and WP14 has no dependency on WP15.

### Integration fix in the WP8 module

One commit, `fix(demux): expose the demuxer's input to the C ABI`: the
crate-visible `WebPDemuxer::input()` returns the parsed bytes (C: `mem.buf`).
The C ABI of `WebPDemuxNextChunk` and `WebPDemuxPrevChunk` recovers the chunk tag
from the four bytes before the iterator's payload, as C reads
`chunk.bytes - CHUNK_HEADER_SIZE`, and needs the input to check that those bytes
lie inside it rather than reading caller memory through a raw pointer. No
behavior change. No other WP8 item changed.

## Not-applicable checks

1. **`NULL` arguments** exist only at the C ABI (PORTING rule 8); every `NULL` case
   of `demux.h` is compared there (`abi_answers_null_and_invalid_arguments_as_c`).
2. **Pointer values.** The probes print positions relative to the input and
   whether `private_` is the demuxer, never addresses.
3. **Big-endian targets** (`WORDS_BIGENDIAN`) are not run; `CHANNEL_SHIFT` is
   translated for both byte orders. Its big-endian form shifts the blended
   channel by `CHANNEL_SHIFT(3) = 0` in `BlendChannelNonPremult`, as C does.
4. **32-bit targets** are not run; `(size_t)size != size` and `CheckSizeOverflow`
   never fail on 64-bit hosts.
5. **Allocation limits.** The demuxer limits a canvas to fewer than 2^32 pixels
   (`MAX_IMAGE_AREA`), so `WebPSafeCalloc`'s 2^34-byte limit is never reached by
   the canvases; a refused host reservation fails `New` as C's `NULL` does, and no
   test reaches it.
6. **`WebPDemuxReleaseIterator(&dec->prev_iter)`** in `GetNext`, `Reset` and
   `Delete` frees nothing in C; the translation keeps comments at those points.
7. **Threads.** `use_threads` goes to the decoder options; 0 and 1 (and -3) are
   matrix dimensions.
8. **The largest vectors in the debug matrix.** The translation's still-image
   test decodes the 120 vectors of at most 200,000 pixels; all 131 go through the
   Rust library's C ABI in `abi_animation_decoder_matches_the_c_library`.
9. **GIF input to `anim_dump`** needs giflib and is not built (see "Evidence");
   PNG output needs libpng in imageio, whose flags both builds share, so the two
   agree whether or not the host has it.

## Undefined behavior excluded from the oracle (PORTING rule 8)

1. **Timestamp overflow.** `prev_frame_timestamp + iter.duration` is an `int`
   sum; 129 frames of the largest duration (0xFFFFFF) overflow it, which is
   undefined. The translation panics in the dev and `checked` profiles and
   wraps in release. The inputs keep the sum below 2^31.
2. **`ZeroFillFrameRect` offsets.** `y_offset * buf_stride` is computed in `int`
   and overflows for canvases of 2 GiB and more. Not reached.
3. **`WebPDemuxNextChunk` and `WebPDemuxPrevChunk` on an iterator whose
   `chunk.bytes` is `NULL`** (a failed `WebPDemuxGetChunk` with a demuxer), or
   points outside the input: C computes the tag address from it and reads
   there. The C ABI returns 0 (deviation 12); the probe never calls it.
4. **`WebPDemuxNextFrame` and `WebPDemuxNextChunk` with `frame_num` or
   `chunk_num` at `INT_MAX`:** the `int` sum overflows. The C ABI returns 0, which
   is what the wrapped value gives in C.
5. **Signed overflow in `TransformOne_C`** (fuzzing, above): WP12's exclusion 1.

## Recorded deviations

1. **Previous iterator.** `prev_iter` is `IteratorFields`, the fields that the
   decoder reads (decision above). No result changes.
2. **Decoder configuration per call.** C points the output at
   `curr_frame + out_offset` with the size `iter.height * stride`, which on the
   bottom rows reaches `x_offset * 4` bytes past the canvas, where C never
   writes. The translation lends the canvas from `out_offset` to its end, with
   that length as the size. `CheckDecBuffer` asks for `stride * (height - 1) +
   width * 4` bytes, which both sizes hold for every frame inside the canvas, and
   the demuxer admits no other, so the same frames pass and fail. The rest of
   the configuration is rebuilt per call: `WebPDecode` overwrites `config.input`
   and the output's dimensions before reading them.
3. **Construction.** `ApplyDecoderOptions` returns the blend function, the
   options and the colorspace that C writes into `dec`, because the decoder value
   is assembled once its demuxer exists. C's `WebPSafeCalloc(1, sizeof(*dec))`
   has no counterpart and cannot fail (as WP8's deviation 6 for the demuxer).
4. **Canvas allocation.** `WebPSafeCalloc(canvas_width * 4, canvas_height)` is
   `webp_safe_calloc(canvas_width * 4 * canvas_height, 1)`: the size tests agree
   (`h > MAX / n` holds exactly when `n * h > MAX`), and the product cannot wrap.
   The Rust helper writes the zeros when it reserves, where C's `calloc` may
   leave the pages untouched until the first frame's `ZeroFillCanvas` and
   `CopyCanvas` write both canvases; the memory is touched earlier, which no
   result shows.
5. **Results.** `GetNext` returns the canvas and the timestamp (C: two output
   pointers and 0 or 1); `GetInfo` returns the info (C: `*info` and 1); `GetDemuxer`
   returns a reference; `Delete` is the drop. The `int` predicates
   `prev_frame_was_keyframe` and `IsKeyFrame` are `bool`.
6. **Canvas after a failure.** C callers can read the canvas that a failed
   `GetNext` leaves behind through the pointer of an earlier call (the header
   promises it only until the next call). The Rust API ends the borrow, so that
   canvas is compared only through the C ABI (`PARTIAL` in
   `abi_animation_decoder_matches_the_c_library`), which hands out the same
   memory.
7. **Pixels.** The blend rows read and write the canvas as `u32` pixels in host
   byte order (`from_ne_bytes`, `to_ne_bytes`) at the byte positions of C's
   `uint32_t*` indexing, so no alignment is needed.
8. **`WebPData` mirror.** `mux_types.h` has no ABI module, so `src/abi/demux.rs`
   defines the `repr(C)` `WebPData` (public, for WP15).
9. **C ABI handles** (decision above). A C `WebPDemuxer*` points at the
   translation's demuxer whether it comes from `WebPDemuxInternal` or from
   `WebPAnimDecoderGetDemuxer`; the caller's `WebPData` struct need not outlive
   the demuxer, as in C, which reads it only at creation.
10. **C ABI iterators.** `Next` and `Prev` rebuild the Rust iterator from
    `frame_num` (or `chunk_num`) and `private_` and write back the fields that C
    writes on success (none on failure); `pad` and `private_` are never written
    after `Get`. `WebPDemuxGetFrame` and `WebPDemuxGetChunk` write the caller's
    iterator whole, so it may be uninitialized.
11. **C ABI options.** `WebPAnimDecoderOptionsInitInternal` writes only
    `color_mode` and `use_threads`, as C does, and `WebPAnimDecoderNewInternal`
    reads only those two fields, where C copies the whole struct; the padding is
    never used, so uninitialized padding is not read.
12. **C ABI chunk tags.** The tag that C reads at `chunk.bytes - 8` is taken from
    the demuxer's input at that position (WP8 integration fix above). An
    iterator whose four bytes are not inside the input (exclusion 3) returns 0.
13. **C ABI restriction.** The caller's bytes are an immutable Rust slice for the
    lifetime of the demuxer or the animation decoder, so they must not change
    while it lives, which `demux.h` requires ("If this data is volatile, the
    demuxer object should be deleted"; the animation decoder's bitstream "should
    remain unchanged"). C would read the changed bytes. The module documentation
    of `src/abi/demux.rs` states it.
14. **Fuzz target.** The FuzzTest domain is libFuzzer's input; the target keeps
    upstream's name (cargo's `non_kebab_case_bins` warning, as WP12 records).

## Notes for the packages that build on WP14

### WP15 (mux and animation encode)

- **Demuxer.** `webp_demux(&data)` (`src/webp/demux.rs`) or
  `webp_demux_internal(&data, allow_partial, version)`; the demuxer borrows the
  `WebPData` value for its lifetime. `anim_diff`, `anim_util.c` and the
  `mux_demux_api_fuzzer` and `animation_api_fuzzer` need the animation decoder:
  `webp_anim_decoder_new(&data, Some(&options))`, then
  `webp_anim_decoder_get_next(&mut dec)` until `webp_anim_decoder_has_more_frames`
  is false; each call returns the full canvas (`canvas_width * 4 *
  canvas_height` bytes) and the timestamp.
- **C ABI.** `src/abi/demux.rs` has the public `repr(C)` `WebPData` of
  `mux_types.h`; `src/abi/mux.rs` can use it rather than defining a second one.
  The handle pattern (a leaked `Box<WebPData<'static>>` over the caller's bytes,
  dropped after the object that borrows it) fits `WebPMuxCreate` with
  `copy_data == 0`.
- **Consumers.** `anim_diff` is built from the same sources as `anim_dump`
  (`anim_util.c`, `gifdec.c`): `tools/oracle/probes/wp14/oracle.cmake` shows how
  to build it twice without giflib. `img2webp` is in the C oracle now
  (`oracle.tool("img2webp")`), and `tests/wp14_support/mod.rs` writes PAM frame
  sequences for it.

### WP16 (safe decoder API)

- **Frames.** `webp_anim_decoder_new(&data, options)` borrows the bytes; `None`
  means an invalid container (the whole file is parsed first, so a truncated file
  fails here), a refused color mode or a memory error. `get_next` yields the
  whole canvas after each frame, already blended and disposed, in the chosen mode;
  the canvas is valid until the next call. Timestamps are the end times of the
  frames: the sum of the durations so far, in milliseconds (the first frame's
  timestamp is its own duration). A failed `get_next` leaves the decoder at the
  same frame. `reset` restarts from the first frame. Still images are one-frame
  animations with timestamp 0 when they have no `ANMF` chunk.
- **Color modes.** Only `MODE_RGBA`, `MODE_BGRA`, `MODE_rgbA` and `MODE_bgrA`;
  the premultiplied modes blend premultiplied pixels. `use_threads` selects the
  threaded VP8 decoder per frame. The canvas starts transparent black: the
  background color of `ANIM` is reported in `WebPAnimInfo::bgcolor` and is not
  applied, as in C.
- **Metadata.** `webp_anim_decoder_get_demuxer(&dec)` returns the decoder's
  demuxer; `webp_demux_get_chunk(dmux, *b"ICCP", 1)` (and `EXIF`, `XMP `) gives the
  payloads, `webp_demux_next_chunk` the further ones, and `webp_demux_get_i` the
  flags, canvas, loop count, background color and frame count.
- **Memory.** Two canvases of `canvas_width * 4 * canvas_height` bytes are
  allocated and zeroed in `new` (deviation 4); the demuxer limits a canvas to
  fewer than 2^32 pixels, so callers that need a smaller budget check
  `webp_get_features` first, as upstream's fuzzer does.

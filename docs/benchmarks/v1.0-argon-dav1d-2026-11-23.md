# Argon AV1 conformance of the dav1d port, 2026-11-23

The dav1d port is the default AVIF decoder of `avif-read` for 1.0
(ADR-0031, amendment of 2026-11-22). Until this record it stood on bit
identity with the libaom reference and with stock dav1d, a recorded
exception to ADR-0025 point 1, with Argon conformance as a follow-up
([#267](https://github.com/sebastian-software/ferrisma/issues/267)). This
is that conformance run: the Argon AV1 streams decoded by the original dav1d
command line, linked against the original C decoder and against the port,
compared with the MD5 values Argon publishes for each stream.

- **Source:** `main` at `d886949e`. The binaries are the repository's own
  gate builds of the original dav1d 1.5.4 command line, unchanged, linked
  against the original C decoder (`tools/build_dav1d.py`, `--asm`, or the
  portable build) or against the port (`tools/build_dav1d_consumers.py`).
- **Archive:** the Argon AV1 coverage-tool streams (base and extended
  profiles, v2.1.1) from the AOMedia AV1 video decoder verification-tool
  page. The downloaded archive's MD5 is `5dd3554c3f73c80f06c7fceeaa1f5dd9`,
  the value the page publishes.
- **Streams:** 2,763, the default set of upstream dav1d 1.5.4
  `tests/dav1d_argon.bash`: 13 directories. The large-scale-tile, stress and
  error streams are not in that set and were not run.
- **Command per stream:** `dav1d -i <stream> --filmgrain G --verify MD5
  --cpumask M --threads T -q`, with the expected MD5 from Argon's reference
  (`md5_no_film_grain` when film grain is off). A nonzero exit status is a
  mismatch.
- **Licensing:** the archive carries no license file. It is used only to
  test a decoder against the streams' published MD5 values. The streams are
  not in this repository, are not redistributed, and their raw logs are kept
  outside it.

## Result

Every configuration passes for both the stock C dav1d and the port: 2,763 of
2,763 streams with the expected MD5.

| Host | Level | cpumask | Threads | Film grain | Streams, C | Streams, port |
| --- | --- | --- | ---: | :---: | ---: | ---: |
| macOS ARM64, native | scalar | 0 | 2 | on | 2,763 / 2,763 | 2,763 / 2,763 |
| macOS ARM64, native | NEON | neon | 3 | on | 2,763 / 2,763 | 2,763 / 2,763 |
| macOS ARM64, native | NEON | neon | 1 | off | 2,763 / 2,763 | 2,763 / 2,763 |
| x86-64 Linux, Rosetta | scalar | 0 | 1 | on | 2,763 / 2,763 | 2,763 / 2,763 |
| x86-64 Linux, Rosetta | AVX2 | avx2 | 5 | on | 2,763 / 2,763 | 2,763 / 2,763 |
| x86-64 Linux, Rosetta | AVX2 | avx2 | 2 | off | 2,763 / 2,763 | 2,763 / 2,763 |
| x86-64 Linux, `qemu-x86_64 -cpu Haswell-v4` | AVX2 | avx2 | 1 | on | 2,763 / 2,763 | 2,763 / 2,763 |

On the first pass four rows of the Rosetta AVX2 runs failed on the C side,
three with film grain and one without, and two of those three also failed on
the port. All six failing results ended in SIGKILL (exit status -9), not in an
MD5 mismatch. The VM's kernel log shows global out-of-memory kills of `dav1d`
(2.1 to 2.5 GB resident each) while the QEMU batch shared the 8 GB Colima VM
with the Rosetta batch. Re-running the three affected streams one process at a
time, with the same commands, passed for the C decoder and the port, with and
without film grain (12 runs, all passing). No stream produces an MD5 mismatch
on any configuration, the port never differs from the C decoder on any stream,
and the SIGSEGV trap did not fire. The table shows the rerun results.

Rosetta is not authoritative for AVX2 correctness, so the AVX2 rows under
`qemu-x86_64` are the cross-check for the Rosetta AVX2 rows.
